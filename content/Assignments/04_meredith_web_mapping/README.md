# Assignment 4: Web Mapping

## Research question

Where does the Mapping Systems course website connect when a browser loads it,
and what can the physical geography of those server connections tell us about
the geography of the web?

I captured a HAR file while loading the course homepage, the Web Mapping
assignment, and the Networks assignment. The Python script extracts each
public `serverIPAddress`, geolocates it with IPinfo, and exports a GeoJSON point
layer. The MapLibre website uses circle size to represent the number of
captured requests handled by each server IP. Clicking a point reveals the
associated hosts, approximate location, IP, and network organization.

## Files

- `inputs/mapping-systems.har`: browser request archive captured on August 7,
  2026. Response bodies, cookies, and authorization headers are not included.
- `capture_har.mjs`: reproducible Playwright capture script.
- `scrape_har_locations.py`: HAR parsing, IP geolocation, GeoJSON export, and
  Folium output.
- `outputs/ip_locations.geojson`: point data used by the MapLibre map.
- `outputs/ip_map.html`: map generated by the course Python workflow.
- `index.html`, `style.css`, and `map.js`: custom launchable web map.
- `outputs/web-map-screenshot.png`: submission screenshot.

## Run the custom web map

From this folder:

```bash
python3 -m http.server 8000
```

Open `http://127.0.0.1:8000/`.

## Interpretation and limits

The map reveals the infrastructure used to deliver the course pages, but it
does not locate the people who made the site or prove where its content is
stored. IP geolocation is approximate, and modern websites often use content
delivery networks whose edge servers are selected according to the visitor's
location. The HAR is also one short capture from one device and one network.
It describes this browsing session, not a universal route through the web.

This distinction matters: an apparently global set of server points may reflect
cloud and CDN architecture more than cultural or organizational geography.
