## HAR → GeoJSON workflow

1. In Chrome DevTools, I cleared the Network log, reloaded the selected public website, let its interactive map resources load, and exported a HAR file.
2. [`scrape_har_locations.py`](scrape_har_locations.py) reads every request URL and `serverIPAddress`, following the core operations in the instructor's [`geolocate-har-file`](https://github.com/mapping-systems/geolocate-har-file) repository.
3. Before publication, the script removes request and response headers, cookies, credentials, query strings, request/response bodies, redirects, precise timestamps, and durations. The raw browser archive is excluded by `.gitignore`.
4. The script groups requests by unique public IP, uses the committed geolocation cache, and writes both the required GeoJSON and a Folium/MarkerCluster reference map.
5. The custom Leaflet application fetches `outputs/ip_locations.geojson`, displays it over a real Esri imagery basemap, groups exact co-locations, and lets the reader filter site, terrain, and imagery requests.

The privacy-reviewed replay file is [`inputs/vanishing-network.sanitized.har`](inputs/vanishing-network.sanitized.har). It allows the extraction to be inspected and reproduced without publishing the original browser archive.

## Reproduce

Install the Python requirements, then regenerate the sanitized HAR, GeoJSON, JavaScript fallback, and Folium reference map:

```bash
python scrape_har_locations.py
```

The committed sanitized HAR and cached geolocation results make the command reproducible without a new browser session. To make a new optional capture first, install Playwright and run:

```bash
npm install playwright
node capture_har.cjs
python scrape_har_locations.py
```

For the intended static-GeoJSON workflow, serve from the repository root:

```bash
python -m http.server 8000
```

Then open:

`http://localhost:8000/content/Assignments/Jennifer_Zhang_Mapping_Systems_Assignments/04_web_mapping/`

The page needs an internet connection for Leaflet and the Esri basemap. Double-clicking `index.html` also works through `outputs/ip_locations.js`; the fallback contains the same generated FeatureCollection and exists only because browsers normally block `fetch()` from a `file://` page.

## Reading the result

The capture contains **63 requests** associated with **7 unique public server IPs**:

- **8** requests for the page's HTML, CSS, JavaScript, and data from GitHub Pages;
- **26** terrain requests from Mapterhorn; and
- **29** World Imagery tile requests from ArcGIS Online.

The geolocation labels group these records into **San Francisco** and **Seattle**. Circle size represents the number of requests at a mapped place. Popups preserve the individual IP records, host names, organizations, and request counts.

IP geolocation cannot locate the visitor, site author, Hailun, or necessarily a physical server. GitHub Pages, Cloudflare, Fastly, Amazon CloudFront, and other CDN/anycast systems can return rotating addresses and database labels. This is a map of the infrastructure observed during one page load, not a route trace and not a map of people.
